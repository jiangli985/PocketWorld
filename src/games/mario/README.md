# 任务二：马里奥横版闯关小游戏 (`src/games/mario/`)

## 模块职责
实现可嵌入房间电脑屏幕内的小游戏，对外默认导出符合 `GameCartridgeProps`（见 `src/types/game.ts`）的 `MarioGame` 组件。横版平台闯关是初始方向，允许重设计甚至推翻核心玩法，技术与集成约定保持稳定。

## 核心验收要求
1. **入口与隔离**：在 `index.tsx` 默认导出 `MarioGame`，使用逻辑分辨率 `800 × 600` 的 Canvas 2D。组件卸载或 `isActive === false` 时按 `AGENT.md` 清理循环、定时器、监听与音频，避免影响房间。
2. **玩法自主设计**：初始参考为四关选关、平台碰撞、金币与强化道具、敌人及终点结算；可以整体重做，在 `进度文档.md` 和 PR 中说明当前方案。内容应完整、丰富，不能只靠重复布局凑数量。
3. **页面与操作**：首页提供「开始游戏」与「退出」；开始后先选关。WASD 操作，A/D 左右、W 跳跃，S 的动作自行设计并说明。游玩中 Esc 立即暂停并只显示「继续游戏」「返回首页」；继续保留本局进度，返回首页结束本局。Esc 不得触发房间返回。
4. **状态联动**：通过 `onScoreChange` 上报分数，通过 `onGameOver` 上报通关/失败结果。游戏内部返回首页不调用 `onExit()`；首页「退出」才调用该接口，返回电脑游戏选择界面。最高分键为 `pocketworld:mario:highscore`。
5. **轻量交付**：保持独立入口以支持外层按需加载；不新增大型引擎，资源压缩复用，限制特效对象数量。遵守根目录 `AGENT.md` 与 `SPEC.md` 第 3 节，验证当前玩法可完成、暂停恢复及反复进出无后台任务残留。
6. **进度与 PR**：维护本目录 `进度文档.md`，写清已有功能、当前阶段和剩余工作，直接更新当前状态并清理冗余，不累加日志。每次提交前核对，PR 必须附本次提交简介与文档链接；仅通过功能分支 PR 交付，由队长审查合并。
